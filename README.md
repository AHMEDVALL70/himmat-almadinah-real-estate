# همة المدينة العقارية — النسخة المحسّنة هندسياً

نفس شكل ومحتوى الموقع الأصلي، لكن مبني على معمارية بيانات حقيقية بدل
`localStorage`، مع إغلاق كل الثغرات التي ناقشناها.

## 📁 محتويات المشروع

```
himmat-almadinah/
├── index.html                          # الموقع (ملف واحد، كما في النسخة الأصلية)
├── supabase/
│   ├── schema.sql                      # قاعدة البيانات الكاملة + RLS
│   └── edge-functions/
│       └── send-reminders/index.ts     # بديل خادم Python الدائم
└── README.md
```

## ✅ كل ثغرة ناقشناها، وكيف حُلّت

| # | الثغرة الأصلية | الحل في هذا المشروع |
|---|---|---|
| 1 | البيانات تُخزَّن في `localStorage` فقط، تختفي بمسح الكاش | جداول `properties` / `offers` / `contracts` في Postgres عبر Supabase، مشتركة لكل الزوار |
| 2 | لا يوجد RLS — أي زائر يقدر يقرأ/يعدّل كل شيء | RLS مفعّل على كل الجداول؛ القراءة العامة مقصورة على `approved`/`published`، ولا كتابة مباشرة على العقود إطلاقاً |
| 3 | `lessor_name` / `lessee_name` نص حر بلا ربط | جدول `parties` موحّد بهوية وجوال وبريد |
| 4 | لا سجل يمنع تكرار التنبيه لنفس الدفعة | جدول `notification_log` بقيد `unique` يمنع الإرسال المكرر |
| 5 | `total_amount` يُدخل يدوياً من كود خارجي، قابل للتضارب | `trigger` يعيد حساب `total_amount` و`vat_amount` من مجموع الدفعات الفعلي تلقائياً |
| 6 | خادم Python منفصل يحتاج يعمل 24 ساعة | استُبدل بـ **Supabase Edge Function** (`send-reminders`) تُستدعى يومياً عبر `pg_cron`، بدون خادم دائم |
| 7 | مفتاح Supabase الحساس (`service-role`) قد يُستخدم بالخطأ من المتصفح | العميل يستخدم `anon key` فقط؛ كل كتابة حساسة (عقد + دفعات) تمر عبر دالة `create_contract_with_schedule` بصلاحية `SECURITY DEFINER` — المتصفح لا يرى أبداً مفتاح `service-role` |
| 8 | تسمية "تقييم بالذكاء الاصطناعي" مضلِّلة (هو معادلة ثابتة) | أعيدت التسمية إلى **"التقييم العقاري الاسترشادي"** مع ملاحظة صريحة في الواجهة أنه معادلة حسابية شفافة وليس نموذج ذكاء اصطناعي |
| 9 | "المساعد الذكي" قواعد ثابتة لكن يُسوَّق كذكاء اصطناعي | أعيد تسميته **"المساعد الإرشادي"** مع توضيح صريح أنه قواعد مبرمجة، بلا استدعاء لنموذج لغوي خارجي وبلا أي مفتاح API في الواجهة الأمامية |

## 🚀 خطوات التشغيل

### 1) قاعدة البيانات
1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com) (مجاني).
2. من **SQL Editor**، الصق محتوى `supabase/schema.sql` وشغّله كاملاً.
3. (اختياري لكن موصى به) فعّل إضافتي `pg_cron` و `pg_net` من **Database → Extensions**، ثم فعّل سطر `cron.schedule(...)` الموجود بآخر ملف `schema.sql` بعد نشر الـ Edge Function.

### 2) الموقع
1. افتح `index.html`.
2. عدّل السطرين بالأعلى:
   ```js
   const SUPABASE_URL = "https://xxxxx.supabase.co";
   const SUPABASE_ANON_KEY = "eyJ...";     // Project Settings → API → anon public
   ```
   تجدهما في **Project Settings → API** بلوحة Supabase. مفتاح `anon` آمن للنشر العلني بشرط بقاء RLS مفعّلاً كما في `schema.sql`.
3. ارفع الملف على GitHub Pages أو أي استضافة ثابتة، تماماً كما كان الموقع الأصلي.
4. بدون هذا الربط، يعمل الموقع تلقائياً بوضع "بيانات توضيحية" مع تنبيه واضح للزائر بدل الانهيار.

### 3) دالة التنبيهات (اختياري)
```bash
supabase functions deploy send-reminders
supabase secrets set SUPABASE_URL=https://xxxxx.supabase.co SUPABASE_SERVICE_ROLE_KEY=eyJ...
```
الإرسال الفعلي عبر واتساب/بريد غير مفعّل افتراضياً (لا أملك بيانات اعتماد مزوّد الرسائل الخاص بك) — الدالة تسجّل التنبيه في `notification_log` وتطبع محتواه في السجلات؛ فعّل استدعاء [WhatsApp Cloud API](https://developers.facebook.com/docs/whatsapp) أو مزود بريد داخل `sendNotification()` عندما تجهز مفاتيحك.

## ⚠️ ما لم يُبنَ عمداً (ولماذا)

- **نموذج تعلّم آلي حقيقي للتقييم**: يحتاج بيانات صفقات فعلية مُوثَّقة لتدريبه؛ بدونها أي "نموذج" سيكون واجهة مزيّفة فوق نفس المعادلة. الأصدق تسميته معادلة حالياً، وبناء نموذج فعلي لاحقاً عند توفر بيانات كافية.
- **إرسال فعلي عبر واتساب/بريد**: يحتاج حساب WhatsApp Business API أو مزود بريد مدفوع باسمك أنت — لم أفترض مزوداً نيابة عنك.
- **لوحة تحكم إدارية** (لاعتماد/رفض العقارات المُدخَلة، ومراجعة العقود): الجداول والصلاحيات جاهزة لها (`status`, `service_role` access)، لكن بناء واجهة إدارية كاملة نطاق عمل منفصل — أخبرني إذا تبيها الخطوة القادمة.
